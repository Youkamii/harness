# tough — 요청한 것만 구현

1. 활성화를 먼저 확인한다. `/tough <요청>` 또는 명시적인 활성화 지시만 인정한다. 질문(`터프 모드가 뭐야?`), 부정(`터프 모드 쓰지 마`), 인용·코드·예시는 활성화가 아니다.
2. 사용자가 요청한 결과와 완료 기준을 작업 범위로 고정한다. 비자명한 구현은 `/kickoff` 절차를 그대로 따른다.
3. 사용자가 요청하지 않았고 기존 제품 계약에도 없는 보안·안전·보호 기능이나 운영 제약을 필수 부수 작업으로 발명·구현하지 않는다. 예: 임의의 8주 거래 제한, 승인 단계, 킬스위치, allowlist, 지연, 시뮬레이션 전용. 이 단어 자체가 금지된 것은 아니며 사용자가 요청했거나 기존 제품 계약에 포함된 기능은 유지·구현한다.
4. 상위 경계에 해당하지 않는 한, 필요하다는 판단만으로 요청 범위로 승격하거나 질문으로 작업을 막지 말고 최종 보고의 **우려**로만 남긴다. 상위 경계·기존 계약과 요청이 실제로 충돌하면 조용히 우회하지 말고 충돌을 보고한다.
5. Tough를 근거로 이미 있는 보호 기능을 삭제·완화·우회하지 않는다. 플랫폼 정책, 샌드박스, 비밀 보호, 저장소 규칙과 훅을 그대로 지킨다.
6. Tough는 검증을 약화하는 모드가 아니다. 테스트, 기능별 커밋, 적대 리뷰와 안전 예외는 기존 절차대로 수행한다.
